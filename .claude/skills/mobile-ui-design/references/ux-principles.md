## 1. 추천 미니앱 UX 원칙 5가지

추천 미니앱은 UX·실사용 지표·리뷰·성능 네 기준을 모두 충족해야 하고, UX는 아래 다섯 원칙으로 본다. 앱인토스 팀은 개발자센터에 공개된 이 체크리스트로 미니앱을 평가한다. [노출] [블로그①]

### ① 로그인이나 알림 동의가 꼭 필요한지 다시 생각한다 [노출] [블로그①]
- 로그인·알림 동의를 요청하기 전에 주요 기능을 먼저 써볼 수 있게 한다.
- 로그인은 입력한 내용을 계정에 저장하거나 이전 기록을 불러와야 할 때 요청한다.
- 알림 동의는 사용자가 새 결과나 소식을 받아보고 싶을 때 요청하고, 어떤 알림을 받게 되는지 알려준다.
- 체크리스트
  - [ ] 로그인하지 않은 상태로 방문했을 때 주요 기능을 써볼 수 있나요?
  - [ ] 로그인이나 알림 동의창은 관련 기능을 선택한 뒤에 나오나요?
  - [ ] 요청 화면만 보고 로그인이나 알림 동의가 왜 필요한지 알 수 있나요?
- 판단 기준 [블로그①]
  - 사용자별로 기록을 이어가기만 하면 된다 → 사용자 식별키로 충분하다 (별도 동의 없이 발급, 기기를 바꿔도 같은 값).
  - 기존 서비스 회원 연결이나 회원 정보가 필요하다 → 토스 로그인. 실명·나이 같은 본인 확인 → 토스 인증.
  - 사용자가 신청해야 받는 알림(재입고·가격 변동·예약 하루 전 안내 등)이 있다 → 알림 동의를 요청한다.
  - 이용 중 생긴 일을 알려주는 알림(결제 완료·예약 확정 등)만 있다 → 알림 동의 없이 보낼 수 있다.
  - 알림 동의는 콘솔에서 만든 메시지 템플릿 기준으로 요청되므로, 요청 화면 문구를 실제로 보낼 메시지와 맞춘다.
  - 진입하자마자 토스 로그인을 요청한 경우 완료율은 49.6%였다 (앱인토스 내부 데이터, 2026년 1~8월).

### ② 전면광고가 나오는 시점을 알리고, 반복하지 않는다 [노출] [블로그②]
- 광고를 보기 전에 무엇을 얻는지 알려준 뒤 사용자가 선택하게 한다.
- 전면광고가 나오기 전에 문구나 광고 아이콘으로 미리 알린다.
- 광고를 한 번 본 뒤에는 결과를 바로 보여준다.
- 추가 광고는 더 자세한 정보나 보상이 있을 때만 제안한다.
- 입력하거나 이용하는 도중에는 광고를 띄우지 않고, 한 단계가 끝나는 지점에 보여준다. [블로그②]
- 체크리스트
  - [ ] 전면광고가 나오기 전, 명확한 광고 안내 표시가 있나요?
  - [ ] 광고를 한 번 본 뒤에는 추가 광고 없이 결과를 확인할 수 있나요?
  - [ ] 추가 광고는 사용자가 더 자세한 정보나 보상을 원할 때만 선택해서 볼 수 있나요?
- 광고 횟수·위치를 바꾼 뒤에는 사용자당 노출 횟수, eCPM, 총수익, 재방문율을 함께 본다. [블로그②]

### ③ 일관되고 명확한 디자인 원칙을 적용한다 [노출] [블로그③]
- 제목·설명·결과의 중요도에 맞게 글자 크기를 정하고 배치한다.
- 같은 기능의 버튼, 같은 종류의 카드는 색과 모양을 통일한다.
- 샘플 문구나 임시 이미지를 남기지 않는다.
- 색과 장식은 화면을 꾸미기보다 제목이나 결과를 강조할 때 쓴다.
- 다른 앱의 구성과 디자인을 가져와 문구와 이미지만 바꾸지 않는다.
- 체크리스트
  - [ ] 제목, 설명, 결과가 각각 어디에 있는지 바로 알아볼 수 있나요?
  - [ ] 같은 기능의 버튼과 카드가 다른 화면에서도 일관성을 가지고 있나요?
  - [ ] 샘플 문구나 임시 이미지가 남아 있지 않나요?
  - [ ] 제목이나 결과보다 배경색과 장식이 먼저 눈에 띄지는 않나요?
  - [ ] 다른 앱의 구성과 디자인을 그대로 사용하지 않았나요?

### ④ 할 일을 순서대로 보여주고, 끝나면 완료됐다고 알린다 [노출] [블로그③]
- 첫 화면에서는 가장 먼저 해야 할 일이 명확하게 보여야 한다.
- 입력란과 버튼은 사용 순서대로 놓고, 버튼을 누르면 어떻게 되는지 명확하게 적는다.
- 같은 형식의 정보를 여러 번 입력해야 하면 한 번에 입력하거나 불러올 수 있게 한다.
- 마지막 작업이 끝나면 완료됐다는 문구나 화면을 보여준다.
- 체크리스트
  - [ ] 앱을 열자마자 뭘 해야 할지 바로 알 수 있나요?
  - [ ] 각 화면에서 다음에 눌러야 할 버튼이나 입력할 곳이 바로 보이나요?
  - [ ] 같은 형식의 정보를 여러 번 입력할 때 한 번에 입력하거나 불러올 수 있나요?
  - [ ] 마지막 작업이 끝난 뒤 완료됐다는 문구나 화면이 나오나요?

### ⑤ 기대한 결과를 보여주고, 그 의미도 함께 알린다 [노출] [블로그③]
(계산기·추첨기·명언처럼 별도의 결과 화면이 없는 앱은 평가 대상에서 제외)
- 앱 이름과 소개에는 결과 화면에서 실제로 확인할 수 있는 내용을 쓴다.
- 점수·등급·유형처럼 결과만으로 뜻을 알기 어려우면 설명을 함께 보여준다.
- 입력·선택에 따라 결과가 달라지면 바꾼 내용이 결과에 반영되고, 달라진 이유를 알려준다.
- 보여줄 내용이 없으면 화면이 비어 있는 이유를 알려준다.
- 체크리스트
  - [ ] 제목과 소개에 적힌 내용을 결과 화면에서 확인할 수 있나요?
  - [ ] 결과 화면의 내용이 무슨 뜻인지 알 수 있나요?
  - [ ] 입력이나 선택에 따라 결과가 달라지는 앱이라면, 바꾼 내용이 결과에 반영되나요?
  - [ ] 입력이나 선택에 따라 결과가 달라진다면, 왜 달라졌는지 알 수 있나요?
  - [ ] 보여줄 내용이 없는 화면에서도 왜 비어 있는지 알 수 있나요?

### 추천 미니앱의 나머지 기준 [노출]
- 실사용 지표: 재방문율(리텐션), 전환율. 콘솔에서 전환 지표를 등록한다.
- 리뷰: 평점과 리뷰 내용이 반영된다. 여러 사용자가 같은 불편을 말하면 그 부분부터 고친다.
- 성능: 앱이 오래 걸리지 않고 열리고, 꺼지거나 멈추지 않아야 한다.

## 2. 출시 검수 체크리스트 중 화면·UX 관련 [출시]

지키지 않았거나 다크패턴이 확인되면 검수가 승인되지 않고, 출시 후에도 노출이 제한되거나 중단될 수 있다.

**UX**
- [ ] 진입하자마자 바텀시트(토스 로그인, 알림 동의문 등)가 자동으로 나타나지 않아요.
- [ ] 특정 화면 전환 시 바텀시트로 사용자의 행동을 강제로 유도하지 않아요.
- [ ] 모든 화면에서 사용자가 미니앱을 나갈 수 있는 방법이 명확해요.
- [ ] CTA 버튼을 보면 다음에 어떤 행동이 일어날지 예측할 수 있어요.
- [ ] 링크나 컴포넌트로 자사 서비스 이동이나 자사 앱 설치를 유도하지 않아요.
- [ ] 사용자가 광고를 예상할 수 없는 상태에서 전면 광고를 노출하지 않아요.
- [ ] 인앱 광고를 클릭하도록 오인시키거나 강제로 유도하지 않아요.

**내비게이션 바**
- [ ] 앱인토스 내비게이션 바를 사용해요.
- [ ] 토스 내비게이션 바의 뒤로가기와 자체 구현한 뒤로가기 버튼이 동시에 보이지 않아요.
- [ ] 뒤로가기를 노출하면 모든 화면에서 정상 동작하고, 최초 화면에서 뒤로가기를 누르면 미니앱이 종료돼요.
- [ ] 닫기 버튼과 뒤로가기 버튼이 노출되고, 동작이 명확해요.
- [ ] 미니앱 기능 버튼은 최대 1개만 노출해요. (선택 사항)
- [ ] 내비게이션 바에 파트너사 자체 로고를 추가하지 않아요.

**서비스 이용 동작**
- [ ] 미니앱 테마는 라이트 모드로 구현돼 있어요.
- [ ] 지도처럼 꼭 필요한 경우를 빼고 제스처 확대·축소를 막아요.
- [ ] 스크롤, 터치, 화면 전환 반응이 2초 이상 지연되지 않아요.
- [ ] 문구에 비속어, 은어, 과도한 유행어가 없어요.
- [ ] 위치, 알림 등 기기 권한은 사용자 동의를 먼저 받아요.
- [ ] 사용자가 권한을 허용하지 않아도 나머지 기능은 계속 정상 작동해요.

**인앱 광고**
- [ ] 사용자가 예상하기 어려운 순간에 인앱 광고를 노출하지 않아요.
- [ ] 인앱 광고는 미리 로딩해 두고, 재생 시점에 실시간으로 로딩하지 않아요.
- [ ] 광고가 끝나면 미니앱 화면으로 정상적으로 돌아와요.
- [ ] 리워드 광고를 끝까지 보면 보상이 정상 지급돼요.
- [ ] 배너 광고는 적절한 위치(상단/중앙/하단)에, 스크롤 가능한 화면에만 노출돼요.
- [ ] 토스 애즈 SSP 정책을 지켜요 (아래 4장).

## 3. 다크패턴: 출시할 수 없는 경우 [UIUX]

1. 서비스에 진입하자마자 바텀시트가 뜨는 경우 (알림 동의 요청 바텀시트 포함)
2. 뒤로 가기를 눌렀을 때 이전 화면을 막는 바텀시트가 뜨는 경우
3. 파트너사가 유도한 CTA 외에 나갈 수 있는 선택지가 없는 경우
4. 예상하지 못한 순간에 광고가 노출되는 경우 (예: 아이템을 받으려고 메뉴를 눌렀는데 전면 광고)
5. CTA 버튼만 보고 다음 행동을 예상할 수 없는 경우 (화면 설명을 CTA에 그대로 반복, CTA 위에 과장·중복된 보조 설명)

## 4. 광고

**유형별로 맞는 자리** [광고]
- 전면형: 화면 전환 시점. 단계가 끊기는 지점(레벨 완료, 예약 완료 등), 사용자가 자연스럽게 멈추는 순간.
- 리워드: 사용자가 직접 '광고 보기'를 선택. 포인트 지급, 기능 추가 제공처럼 보상이 필요한 순간.
- 배너: 화면 상단·하단 고정. 메인 화면, 리스트 화면, 사용 시간이 긴 화면.
- 사용자에게 광고가 너무 자주 노출되지 않도록 주의한다. 테스트에는 반드시 테스트용 광고 ID를 쓴다.

**토스 애즈 SSP 정책에서 금지하는 것** [광고] [전면]
- 광고를 "추천 서비스", "금융 팁" 등으로 위장해 콘텐츠와 구분을 흐리게 하는 것
- 광고 단위의 색상·글꼴, 타이틀·라벨·CTA 문구와 디자인을 임의로 바꾸는 것
- 버튼·게임 영역 같은 상호작용 요소 바로 옆에 광고를 두어 의도치 않은 클릭을 만드는 것
- 같은 화면에 같은 포맷 광고를 2개 이상 두는 것
- 화면 종료나 이전 화면 이동을 어렵게 하는 것, Back 버튼을 막거나 비정상 제어하는 것
- 광고 영역을 주기적으로 새로고침하는 것
- 광고 클릭과 동시에 보상·혜택을 주는 것 ("광고 클릭하면 포인트 제공")
- 광고를 숨기거나 다른 UI 뒤에 겹치는 것
- 정책에 적혀 있지 않아도 노출·클릭·성과를 인위적으로 유도하거나 사용자를 오인하게 하면 위반으로 볼 수 있다.

**광고에도 적용되는 토스 원칙** [광고]
- Simplicity: "지금 보기", "광고 보기"처럼 추가 설명 없이 이해되는 CTA
- Clear Action: 광고를 누르면 무슨 일이 생기는지 예측할 수 있게 (외부 이동 시 고지 문구)
- No Deception: 예상하지 못한 순간·형태·위치에 광고를 띄우거나 콘텐츠처럼 위장하지 않음
- Value First: 서비스 목표를 방해하지 않음 (예: 결제·계좌 개설 흐름 중 광고 삽입 금지)

**전면광고를 배치하는 네 가지 방법** [블로그②]
1. 입력하거나 이용하는 도중에는 띄우지 않는다.
2. 버튼 문구나 광고 아이콘으로 광고가 나온다는 걸 미리 알린다.
3. 무엇을 얻는지 알려주고 볼지 말지 선택하게 한다.
4. 한 번 봤다면 결과를 바로 보여준다.

## 5. 푸시·알림 메시지 [푸시]

- 푸시알림은 **기능성 메시지로만** 보낼 수 있다. 수신자가 요청한 정보이거나 서비스 이행에 필요한 필수 메시지여야 한다.
- 구매 유도, 서비스 이용 유도, 혜택 안내, 리텐션 같은 광고·마케팅 목적 내용은 넣을 수 없다.
- 허용 예: 결제 완료·환불·포인트 적립, 배송·예약 확정, 정기 결제 예정·서비스 만료 예정.
- 메시지 템플릿 문구는 검수를 받는다.
  - 제목은 7자 이내 명사형 ('~하기' 형태는 행동 유도로 오해받을 수 있음).
  - 내용은 25자 이내 '~요.' 체 (변수는 2글자로 계산).
- 특정 시점에 알림을 받겠다고 동의받는 경우(재입고·가격 변동·예약 오픈 알림 신청, 매일 정해진 시간 안내 등)에는 **알림 동의문**이 필요하다.
- 사용자가 알림 수신을 해제할 수 있는 기능과 해제 방법 안내를 권장한다.
- 대량 메시지는 야간(오후 9시~오전 8시)에 발송되지 않고 오전 8시 이후로 보류된다. 단건 메시지는 야간에도 발송된다.

## 6. UX 라이팅 [UIUX]

- 모든 문구는 해요체.
- 능동형으로 쓴다 (`됐어요` → `했어요`). 서비스 종료·만료, 사용자에게 미치는 영향, 안심시킬 때는 수동형 가능.
- 긍정형으로 쓴다 (`없어요` → `있어요`). 정책상 쓸 수 없거나 일부 기능만 못 쓸 때는 부정형으로 분명하게.
- 과한 경어(`~시겠어요?`, `계시다`, `여쭈다`, `~께`)를 쓰지 않는다. 사용자 상황을 추정하거나 설문처럼 선의가 필요할 때는 `~시나요?` 가능.
- `{명사}+{명사}` 나열을 피하고 한자어는 풀어 쓴다.
- `되어요` → `돼요`.
- 다이얼로그 왼쪽 버튼은 `닫기`로 통일한다 (`취소`는 쓰지 않음).
