# 화면 자기 점검 (UI Self-Check)

"작동한다"에서 멈추지 않고, **눈으로 보고 체크리스트로 비평한 뒤에만** 끝났다고 말한다.

## 언제 실행하나

1. **최초 기획 직후:** 화면 구성(무엇을 어디에 둘지)을 정했을 때. 아직 코드가 없으면 기획안을 아래 체크리스트에 대 보고, 걸리는 항목을 기획에서 먼저 고친다.
2. **화면을 만들거나 고친 뒤:** 사용자에게 "완성했어요"라고 말하기 전에 매번.
3. 사용자가 점검을 요청했을 때.

## 순서

1. **스크린샷을 찍는다.** 모바일은 가로 375~390px 기준. 주요 화면과 상태(처음, 선택지, 결과, 빈 상태, 팝업)를 모두.
   ```bash
   npx playwright screenshot --viewport-size=390,844 http://localhost:3000 shot.png
   ```
   스크린샷을 찍을 수 없으면 사용자에게 요청한다. 보지 않고 판단하지 않는다.
2. **이미지를 직접 열어 보고** 아래 13개 항목에 화면별로 ✅/❌ 와 근거를 적는다.
3. **❌ 항목을 고친다.** 사용자가 범위 밖이라고 정한 항목(예: "디자인 시스템 전환은 하지 않음")은 고치지 않되, 그 안에서 바꿀 수 있는 부분은 바꾼다.
4. **다시 스크린샷을 찍어 확인한다.** 최소 1회 반복한다.
5. 사용자에게는 표로 결과를 보여주고, 무엇을 왜 고쳤는지 한두 줄로 말한다. 고치지 못한 항목은 이유와 함께 밝힌다.

## 체크리스트 (하나라도 "아니오"면 고친다)

- [ ] 디자인 시스템 컴포넌트(앱인토스면 TDS)를 쓸 수 있는데 직접 만든 곳은 없는가?
- [ ] 색·글자 크기를 숫자로 직접 적은 곳은 없는가? (디자인 시스템의 색상·글자 스타일만 썼는가?)
- [ ] 눈을 가늘게 뜨고 봐도 주인공 요소(가장 많이 눌릴 것)가 가장 먼저 보이는가?
- [ ] 버튼/항목이 배경과 확실히 구분되는가?
- [ ] 제목·소제목·본문 크기 차이가 한눈에 느껴지는가?
- [ ] 비슷한 버튼이 너무 많이 반복되지 않는가? (같은 모양 6개 이상 나열 금지)
- [ ] 회색 글자가 너무 연하거나 작아서 읽기 힘든 곳은 없는가? (본문 보조 글자 최소 13px)
- [ ] 엄지로 누르기 편한 크기와 위치인가? (핵심 행동은 화면 아래 큰 버튼)
- [ ] 관련 있는 것끼리 묶이고, 묶음 사이 간격이 묶음 안 간격보다 큰가?
- [ ] 이상한 줄바꿈, 잘린 글자, 넘치는 요소가 없는가? ("은(는)" 같은 조사 처리 흔적, 숫자 중간 줄바꿈 포함)
- [ ] 문구가 해요체·능동형·긍정형인가? 다이얼로그 왼쪽 버튼은 [닫기]인가?
- [ ] 다크패턴(진입 즉시 바텀시트, 나갈 수 없는 화면, 갑작스러운 광고, 모호한 CTA)이 없는가?
- [ ] 플랫폼(예: 토스 앱) 안의 다른 화면 옆에 놓아도 어색하지 않은가?

## 함께 보는 항목 (경험에서 나온 것)

- **그림·사진 위에 글을 얹을 때 인물의 얼굴과 표정을 가리지 않는가?** 가리면 대사를 그림 아래로 옮긴다.
- **글과 그림이 일치하는가?** 글이 말하는 상황(붐비는 지하철, 늦은 밤 등)과 그림이 다르면 둘 중 하나를 고친다.
- **선택이나 행동을 했는데 화면이 그대로인 곳은 없는가?** 누르면 반드시 눈에 보이는 변화가 있어야 한다.
- **개발용 텍스트(단계 메모, 변수명, "1차 공개 4개" 같은 내부 표현)가 화면에 없는가?**
- **숫자에 근거가 있는가?** 근거가 없는 숫자는 "가정"이라고 화면에 밝힌다.
